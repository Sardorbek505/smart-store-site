# 3D-касса и приближение по точкам — v44

Блок «От товара. До чека» получил настоящую WebGL-сцену. Монитор с подставкой, сканер, синий подиум, принтер и изогнутый чек состоят из объёмной геометрии. На экране — исходные `img/demo-sale.png` и `img/demo-payment.png` с мок-данными проекта. Это демонстрация: клики не создают продажи и не обращаются к магазину.

«Товар» приближает карточку шуруповёрта, «Чек» — строки чека, «Оплата» — верхнюю часть окна смешанной оплаты. Камера одновременно меняет расстояние, положение и направление; переход занимает 800 ms. Повторный выбор текущего ракурса ничего не перезапускает; быстрый выбор другой точки начинает движение от текущего положения. Кнопка «Общий вид» и Escape возвращают всю кассу и переводят клавиатурный фокус на первую точку. Полный исходный экран по-прежнему открывается через просмотрщик; для оплаты ссылка ведёт на правильный снимок оплаты.

## Ограничение нагрузки

- Three.js 0.180.0 закреплён в npm и собирается в отдельный локальный `assets/checkout3d.<hash>.js`. В херо этот код не загружается. Никаких CDN, OrbitControls, видео и постобработки.
- Контекст WebGL2 создаётся только у видимой сцены после остановки прокрутки. При отсутствии WebGL библиотека не скачивается.
- Рендер выполняется один раз при показе/изменении размера либо во время перехода камеры. В покое нет графического цикла. Тест инструментирует реальные `drawElements`/`drawArrays` обоих браузеров и проверяет нулевое число новых вызовов в покое.
- Прокрутка, удержание касания, невидимость сцены, скрытие документа и открытый просмотрщик приостанавливают переход. Возврат продолжает его с того же момента. При reduced motion используется один финальный кадр.
- Максимальный DPR рендера — 2. Общий вид содержит около 8 648 треугольников и 16 вызовов отрисовки; приближённый экран — около 2 172 треугольников и 5 вызовов. Вместо динамических теневых карт используется одна заранее вычисленная мягкая тень.
- При утрате GPU-контекста показывается кадр текущего ракурса; восстановление возвращает реальную 3D-сцену в тот же ракурс. При ошибке движка или текстуры кнопки продолжают переключать резервные изображения.

## Резервные изображения и доступность

Четыре `img/checkout-{overview,0,1,2}-v44.webp` — прозрачные кадры, снятые с того же настоящего 3D-рендера, а не независимо сгенерированные фотографии. Во время исправной 3D-работы дополнительные кадры не загружаются; они нужны для режима без GPU или при ошибке. Обычный HTML сразу содержит общий вид. Без JavaScript остаётся ссылка на исходный экран.

Кнопки имеют размер не меньше 44 × 44 px, сохраняют навигацию стрелками/Home/End и `aria-pressed`. Canvas декоративный; смысл выбранного шага доступен через настоящие заголовок, описание, цену/сумму и статус под сценой. Снижение движения действует также на резервные кадры. В общем виде камера подбирает расстояние по границам всех физических объектов с полями; при приближении края монитора намеренно уходят за границу кадра.

## Разработка

```sh
npm ci
npm run build:checkout
python -m http.server 4173
# В другом терминале после изменения модели:
python tools/render-checkout-posters.py
npm run build:styles
npm run check:checkout
npm test
```

Скрипт снимков использует Chromium/Playwright, проверяет, что непрозрачное тело общего вида не касается краёв, и сохраняет WebP 1600 × 1200 с качеством 91. Исходные PNG остаются во временном каталоге. Сборщик проверяет содержимое JS и сохраняет предыдущую опубликованную версию; CSS использует существующий механизм двух версий. Лицензия Three.js находится в `third-party/three-LICENSE.txt` и указана в заголовке бандла.

## Проверка

`tests/checkout-3d-check.py` запускает реальный WebGL в Chromium/WebKit: пять размеров, три приближения, первый клик по уже активной точке «Товар», общий вид, клавиатура, быстрые переключения, нулевой рендер в покое/при паузе, reduced motion, просмотр исходного экрана, настоящая потеря и восстановление GPU-контекста, отсутствие WebGL, отказ движка/текстуры и использование без JS. Скрытие документа проверяется синтетическим lifecycle-событием: headless-окна не воспроизводят системное переключение приложений iPhone.

Дополнительно проверяются полная видимость обычных мокапов и нового общего вида, первый экран до/после модулей, стабильность прокрутки, размеры контролов, доступность и ограничения одного экрана. Логи и скриншоты разработки: `/workspace/scratch/v44/`. Проверки браузерных движков не являются замером FPS физического iPhone.
