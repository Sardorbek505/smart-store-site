## Проверка опубликованного preview

- 12 публичных адресов: страницы и файлы подтверждения доступны, отсутствующий
  адрес возвращает 404, `/index.html`, `/demo/` и адрес инструкции дают 301.
- `nosniff`, `DENY`, `frame-ancestors 'none'`, HSTS и `X-Robots-Tag: noindex`
  присутствуют также на перенаправлениях и 404. Сертификат HTTPS проверяется.
- Chromium и WebKit: конкурирующие отправки формы, отмена старого ответа,
  зарезервированный код, приватность referrer, отключение статистики, DNT/GPC,
  отказ хранилища и CSP проходят. Документы доступны без JavaScript при ширине
  320, 390 и 1440 px.
- Внешние сервисы в браузерных сценариях заменены fixtures. Искусственные
  визиты, продажи, подключения магазинов и сообщения в production не создавались.

## Оставшиеся действия

1. Проверить тариф и квоты именно Workers. Видимая отметка Free у DNS-зоны
   сама по себе не подтверждает тариф Workers или доступный остаток квоты.
2. Владелец проверяет вход уже подключённого магазина и свой тестовый компьютер.
   Публичный health сам по себе не подтверждает работу всей программы с телефона.
3. Отдельно обновить локальные инструменты: npm сообщает об уязвимостях цепочки
   `wrangler → miniflare → undici`. Эти пакеты не входят в браузерный React-бандл
   или исполняемый код опубликованного Cloudflare Worker.

Windows-установщик для этой публикации не пересобирался. Существующие
runtime-секреты вручную не перенастраивались.

## Основной домен после подключения Worker

На `https://metov.store/` проверены 16 публичных адресов с HTTPS-проверкой:
главная, условия, инструкция и файлы обхода/подтверждения доступны; неизвестный
адрес даёт 404. Старый `/demo/`, `/index.html`, адрес инструкции без слеша,
www и HTTP перенаправляются за один 301. Защитные заголовки действуют также на
404 и перенаправлениях; `X-Robots-Tag: noindex` на основном домене отсутствует.
DNS metov.store и www указывает на адреса Cloudflare.

Chromium и WebKit проверили опубликованный модуль просмотра: байты совпадают
с проверенными исходниками v65; Back закрывает скриншот с сохранением прокрутки,
Forward возвращает тот же экран, Escape возвращает фокус. Ошибок JavaScript нет.
Внешние сервисы заменены fixtures, синтетические production-события не отправлялись.

При первом подключении домена проверка приватности выявила автоматически
вставленный Cloudflare Web Analytics beacon. Meta CSP блокировал его исполнение,
однако сам факт вставки нарушал проверку отсутствия внешних SDK. Исправление
опубликовано из окружения владельца: `Cache-Control: public, no-cache, no-transform`
для HTML и `no-store, no-transform` для HTML 404 сохраняет проверенное содержимое.
Повторная HTTP-проверка подтвердила новый заголовок и отсутствие внешнего скрипта
на главной, в условиях, инструкции, HTML-файле подтверждения и ответе 404.

Полная readiness-проверка живого metov.store после исправления прошла в Chromium
и WebKit: повторная отправка формы не создаёт второй запрос, устаревший ответ
игнорируется, служебный код отклоняется, referrer передаётся только как origin,
отключение статистики действует между вкладками, DNT/GPC и отказ хранилища
останавливают необязательные события. В проверенных сценариях нарушений CSP
и ошибок JavaScript нет. Статические страницы доступны без JavaScript при
320, 390 и 1440 px без горизонтального переполнения. Все внешние ответы в
браузерных сценариях заменены fixtures; реальные магазины не опрашивались.

После переключения повторно проверены health сервера подключения и HTML «Завода»:
оба возвращают 200, ожидаемый сервис и ранее опубликованный бандл сохранены.
Эти проверки не заменяют вход в реальный магазин на физических устройствах.
