# Загрузка и устойчивость — v34, 25 октября 2026

## Изменения

- Удалены 332 селектора прежних hero, изометрии, вееров телефонов, графической «14» и переключателей, которых больше нет в HTML или динамических состояниях. Классы, создаваемые скриптами (`navigation-sentinel`, `proof-icon` и состояния), сохранены. Убрана прежняя базовая тема кнопок: общие размеры, цвета и состояния принадлежат `buttons.css`. Контекстная компоновка остаётся в стилях соответствующих разделов.
- Браузер загружает одну готовую таблицу вместо восьми. Исходники остаются раздельными и читаемыми; `tools/build-styles.mjs` сохраняет порядок каскада и минифицирует их через закреплённый esbuild 0.25.12. Сборщик не входит в клиентский JavaScript. Отдельная таблица условий не включает hero и истории продукта.
- Имя готового CSS содержит SHA-256 содержимого. Сборщик обновляет ссылки в HTML; ручные `?v=` для CSS больше не нужны. `assets/styles.json` хранит текущую и предыдущую версии, чтобы закэшированный HTML мог получить свою таблицу. CI проверяет исходники, результат, ссылки и сохранённые файлы.
- `app.js` параллельно загружает модули. Только `downloads` и `store` требуют `core`; его отказ больше не отключает весь интерфейс. Ошибки визуальных модулей по-прежнему изолированы от установки и входа.
- До выполнения JavaScript три основных CTA уже ведут в `#installation`. При медленной загрузке на телефоне открывается адрес для Windows; без JavaScript доступна инструкция и официальный выпуск. На Windows при запуске модуля сразу готова резервная ссылка на официальный выпуск, затем она заменяется проверенным EXE. Телефон, Mac и Linux больше не запрашивают API Windows-релиза.
- Подсказка `sizes` в hero учитывает реальную область фотографии внутри `object-fit: contain`, а не всю ширину карточки. Ширина изображения не менялась; файлы не пережимались. Браузер выбирает существующие 768/1536 px по размеру отрисовки и DPR.
- `scripts/media.js` заменяет недоступную сгенерированную сцену исходным экраном приложения. `srcset` сбрасывается, чтобы WebKit не продолжал выбирать неработающий WebP. Работает для повторов hero, карточек и ссылок на исходные экраны. Одинаковая обработка статических изображений убрана из `story.js`; там остаётся загрузка следующего шага по нажатию. Текстовое описание резервного экрана больше не обещает несуществующий ноутбук или телефон.

## Проверка

- После удаления старых селекторов и объединения CSS сравнены все вычисленные свойства и прямоугольники элементов главной страницы и условий на 320×568, 390×844, 768×1024, 844×390 и 1440×900: различий нет. После централизации кнопок дополнительно проверены итоговая геометрия и интерактивные состояния.
- `npm test`, `npm run check:styles`, проверка синхронизации первого кадра hero и синтаксиса модулей.
- `tests/loading-check.py`, Chromium и WebKit: одна таблица; отсутствие API на телефоне; Retina; нажатие до модулей; отказ core; недоступные WebP; исходник в просмотре. Сервисы заменены тестовыми ответами, EXE не скачивается, сообщения не отправляются.
- `tests/browser-check.py`: установка Windows, передача ссылки, проверка магазина, ошибки/отмена/устаревшие ответы, меню, FAQ и режим без JavaScript.
- WebKit: `first-paint-check.py` — нулевые изменения геометрии и пикселей до/после модулей на четырёх размерах; `hero-coverage-check.py` — полное покрытие области отрисовки при моделируемой панели Safari.
- WebKit: `journey-check.py`, `story-check.py`, `native-scroll-check.py`, `hero-motion-check.py` — предложение/WhatsApp, масштабирование, истории продукта, стабильные высоты, жесты/поворот, остановка ленты при прокрутке и reduced motion. Повторный изолированный замер Chromium с 4× замедлением CPU на 390×844/DPR 3 и 1440×900/DPR 2: 0 долгих задач, 95-й процентиль интервала кадров 16,7/16,8 мс. Параллельный запуск других браузерных проверок даёт шум, поэтому из него вывод об ускорении не делался. У ленты нет покадровых JS-обработчиков и изменений DOM во время автоматического движения.

Локальный запуск после правки CSS:

```sh
npm ci
npm run build:styles
python -m http.server 4173
```

В другом терминале:

```sh
PLAYWRIGHT_SKIP_VALIDATE_HOST_REQUIREMENTS=1 BROWSER=webkit python tests/loading-check.py
```

`PLAYWRIGHT_SKIP_VALIDATE_HOST_REQUIREMENTS` нужен только для текущего облачного стенда с подготовленными WebKit-библиотеками; на обычной установке Playwright он не требуется.
