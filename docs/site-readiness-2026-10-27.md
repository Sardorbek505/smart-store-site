# Проверка готовности и видимости Smart Store — 27 октября 2026

Проверен статический лендинг https://metov.store и его публичные документы.
Исходные восемь изображений использованы как список тем для проверки, а не
как обещание первого места или обязательных функций для любого сайта.
Windows-приложение, connect и «Завод» — отдельные сервисы.

Статистика не объявлена «полностью анонимной»: сервер получает IP и другие
технические сведения соединения. Сроки хранения и серверная обработка требуют
проверки самих сервисов. Страница объясняет связь с ними и способ обращения
по вопросам данных. Внешний WhatsApp не отправляет сообщение автоматически.

IndexNow подготовлен для уведомления участвующих поисковиков о трёх URL.
Файл подтверждения размещается на домене; `tools/notify-indexnow.py --submit`
сначала проверяет опубликованный ключ и точное совпадение HTML. Без флага
выполняется только dry run. Уведомление отправляется один раз после публикации,
а не с каждого браузера или регулярно без изменений. Ответ 200 подтверждает
получение URL, 202 — получение с ожидающей проверкой ключа; оба не означают
индексацию или присвоение позиции. Google Search Console это не заменяет.

Продолжение: уведомление автоматизировано для изменений публичного HTML и файлов
обхода на `main`. Перед POST workflow ожидает совпадающую публикацию; изменения
README и тестов не вызывают повторную отправку. Семь тестов с локальными ответами
проверяют dry run, устаревшую страницу, неверный или перенаправленный файл,
ограниченное ожидание и отсутствие повторного POST при ошибке API.
[Подключение кабинетов и текущие границы](search-console-setup.md).

При повторной публичной проверке 27 октября запрет `X-Robots-Tag` отсутствовал,
поисковые боты разрешены robots.txt, файл подтверждения IndexNow отдавался с 200
и совпадал с конфигурацией. Запрос `site:metov.store` в доступном веб-поиске
результатов не вернул; это не доказывает отсутствие индексации. Точный статус
из кабинета Google не получен. Запрошен публичный HTML-тег из аккаунта владельца;
Windsor.ai предложен для чтения будущих отчётов, подключение не подтверждено.

## Что уже было в порядке

- Основное содержание находится в исходном HTML и читается без JS. Переход
  на серверный React ради индексации не требуется.
- HTTPS и переход к основному домену работают; домен собственный, favicon и
  социальная обложка существуют. На главной были корректные canonical,
  title/description и один H1.
- Изображения лендинга преимущественно WebP, размеры заданы. Оригиналы экранов
  оставлены чёткими; уменьшать их до нечитаемого вида ради формата не нужно.
- 3D загружается возле своей секции, с ограниченным Retina-бюджетом; анимации
  приостанавливаются вне видимости, при прокрутке и за диалогами.
- Для загрузки/ошибок/пустых ответов есть состояния. Проверка магазина имеет
  таймаут, отмену и защиту от устаревшего результата, поддерживает BFcache.
- Установщик выбирается только из ожидаемого официального выпуска.
- В опубликованных исходниках проверка шаблонов приватных ключей и токенов
  не выявила совпадений; source maps в assets не публикуются. `.env` исключены
  из будущих коммитов. Это не аудит сторонних серверов или истории всех репозиториев.
- Используются системные шрифты; лицензии адаптированных компонентов сохраняются
  в `third-party/`. Рисунки и снимки принадлежат проектному набору материалов.

## Скорость и проверка браузеров

До изменений: Lighthouse 13.5.0, мобильный профиль, публичная главная:
Performance 77, Accessibility 100, Best Practices 100, SEO 100; LCP 3,5 с,
TBT 450 мс, CLS 0. Это лабораторный запуск, не статистика посетителей.
В том запуске длинная задача была отнесена к удалённому SDK статистики.

После локальных изменений: Performance 87, остальные категории 100,
TBT 10 мс, CLS 0, LCP 3,8 с. Локальный Python-сервер отдаёт файлы без сжатия и
с другим кэшем, поэтому разницу оценок и LCP нельзя считать прямым измерением
ускорения production. Публичный результат после Pages: **Performance 99**, Accessibility 100,
Best Practices 100, SEO 100; LCP 2,1 с, TBT 0 мс, CLS 0. Это отдельный
лабораторный запуск с тем же мобильным профилем, а не обещание таких значений
каждому посетителю. Сводка с датами и исходными числовыми значениями:
[lighthouse-v58.json](lighthouse-v58.json).
Оценка SEO 100 также не означает высоких позиций в поиске.

10 Node-тестов и проверки сборок проходят. Chromium и WebKit проверяют
приватность реальных browser-запросов с тестовыми ответами, DNT, GPC, недоступное
хранилище, отключение в соседней вкладке, отсутствие повторного lookup,
устаревший ответ и служебный адрес. Документы без JS проверяются на ширинах
320, 390 и 1440 px. Дополнительные проверки покрывают установку и 3D.
Физический iPhone в облачной среде недоступен; полевые INP/LCP требуют
реальных измерений в панели поисковика или у посетителей.

CSP исключает строковый eval. Ожидания в Playwright записаны как функции,
чтобы тестовый runner не требовал ослаблять политику сайта.

После публикации проверены реальные статусы публичных страниц и файлов:
три страницы и robots/sitemap/llms — 200, неизвестный адрес — 404 с собственным
шаблоном. Production-проверки Chromium подтвердили настройку статистики и
работу формы, WebKit — компоновку, FAQ и навигацию в четырёх размерах.

## Что нужно для дальнейшего роста в поиске и ответах ИИ

Технический этап создаёт доступный и понятный источник. Позиции и цитирование
зависят также от конкурентов, конкретного запроса, региона, достоверности
продукта и внешних упоминаний. Автоматической настройки «рекомендуй всегда» нет.

| Сценарий поиска                                   | Где есть ответ                                                  |
| ------------------------------------------------- | --------------------------------------------------------------- |
| Программа для магазина инструментов и запчастей   | Главная и подробное описание программы                          |
| Касса и склад без интернета на Windows            | Описание: интернет и данные; FAQ                                |
| Продажи, склад, остатки и закупки                 | Примеры возможностей и разделы продажи/склада                   |
| Учёт долгов и аренды инструмента                  | Раздел о долгах и аренде с предложением проверить свой сценарий |
| Проверить магазин с телефона                      | Мобильная секция и инструкция с условием включённого компьютера |
| Стоимость Smart Store, пробный период и установка | Предложение, установка, FAQ и условия лицензии                  |

Дальнейшие действия владельца и проекта:

1. Подтвердить основной домен в Google Search Console и Bing Webmaster Tools
   (либо предоставить уже существующий доступ). Затем отправить
   `https://metov.store/sitemap.xml`, проверить три URL и ошибки обхода.
   В текущей сессии доступа к этим аккаунтам нет: регистрация и отправка карты
   не заявляются выполненными. Если Search Console предоставляет настройку
   включения в генеративные функции, проверить её при подключении.
2. Уточнить официальное имя владельца/ИП/ТОО, страну, условия оплаты и возврата.
   Не публиковать вымышленные реквизиты, цену или юридические обещания.
   Эти сведения уже запрошены, ответ пока не получен.
3. Оценивать реальные запросы, показы, переходы и конверсию в скачивание после
   накопления данных; отдельно смотреть цитирование в доступных AI-отчётах
   Bing. Обновлять описание по подтверждённым изменениям продукта.
4. Публиковать с разрешения клиентов реальные внедрения: тип магазина,
   исходная задача, снимки и измеренный результат. Нет оснований изобретать
   проценты роста, отзывы, партнёрства или ссылки из СМИ.
5. По фактическим вопросам клиентов добавлять полезные инструкции. Не создавать
   пачки одинаковых страниц под города/ключевые слова и скрытых команд моделям.
   Упоминания в отраслевых каталогах должны описывать реальный продукт; никакие
   сообщения или заявки третьим лицам в этой работе не отправлялись.

Разрешение OAI-SearchBot относится к поисковым функциям ChatGPT. Оно не означает
обучение модели на сайте или обязательную рекомендацию. Training-краулеры и
поисковые краулеры имеют разные назначения. Текущий wildcard robots разрешает
публичный обход и не закрывает ресурсы страницы.

## Пункты изображений, требующие другого уровня доступа

| Пункт                                    | Граница                                                                                                                                                                                                                  |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Rate limits, лимиты API и расходы AI     | Настраиваются в connect, «Заводе» и AI-аккаунтах. Лендинг не делает платные Gemini-запросы.                                                                                                                              |
| SQL, индексы, пагинация, миграции        | Базы на лендинге нет. Проверять в Windows-программе и серверах.                                                                                                                                                          |
| Upload limits и документы                | На лендинге нет приёма файлов. Это аудит отдельной функции приложения.                                                                                                                                                   |
| Повторные платежи, refunds и чеки оплаты | Сайт не принимает платежи. Условия лицензии требуют подтверждения владельца.                                                                                                                                             |
| Восстановление backups                   | Резервные копии принадлежат приложению; лендинг не может проверить восстановление базы.                                                                                                                                  |
| Серверные заголовки                      | GitHub Pages не поддерживает произвольные response headers из репозитория. Meta CSP не даёт frame-ancestors, HSTS или X-Content-Type-Options. Нужен отдельный доступ к edge/хостингу; фиктивные `_headers` не добавлены. |
| Cookie/возраст/подписка                  | Нет рекламных cookie, детского профиля или рассылки. Баннер и unsubscribe не добавлены ради галочки. Юридические требования зависят от владельца и обработки данных на серверах.                                         |
| Настоящие 301                            | Старый `/demo/` использует статический переход. GitHub Pages не задаёт произвольные redirects из репозитория. Канонический адрес указан, внутренние ссылки на старую версию удалены.                                     |
