# Проверка 19 пунктов готовности — 27 октября 2026

Область: лендинг metov.store, исходный код и изолированная сборка Smart Store
1.30.0 (`ee421dc`), клиентская аналитика и подготовленный приём в «Заводе».
Лендинг не регистрирует аккаунты и не хранит общую базу магазинов.
Код Windows-программы этим изменением не менялся.

| Пункт | Состояние и проверка |
| --- | --- |
| 1. Вход и выход | Есть в интерфейсе телефона. Сервер проверяет PIN либо логин/пароль и роль; выход отзывает сессию. Владелец может завершить все входы пользователя. Проверены тесты и запуск приложения с отдельным профилем. |
| 2. Восстановление пароля | Владелец задаёт новый пароль в «Система» → «Логины для телефона»; старые сессии отзываются. Добавлены инструкция и ссылка из формы входа лендинга. |
| 3. Подтверждение email | Не применяется: пользователей телефона создаёт владелец магазина на компьютере. Почта для этого не нужна. |
| 4. Загрузка | Проверяются состояния поиска магазина и установщика. Отказ визуальных модулей или диагностики не блокирует вход и установку. |
| 5. Пустые состояния | Есть пустая база при первом запуске и ответ «магазин не найден». Пустой ответ API выпуска сохраняет ссылку на официальные выпуски. Первый запуск и эти ответы проверены. |
| 6. Сообщения об ошибках | Форма различает неверный код, отсутствие магазина и недоступность сервиса. Отказ печати не отменяет проведённую продажу; неверный код лицензии даёт объяснение. Проверены браузерные и Electron-сценарии. |
| 7. Проверка формы | Код/адрес магазина нормализуется; чужой домен и служебный адрес не принимаются. Повторная отправка во время проверки игнорируется, закрытие формы отменяет поздний переход. |
| 8. Ограничение запросов | Сервер телефона ограничивает неудачные входы, есть отдельная защита от внешнего перебора. Проверено тестами доступа. Ограничения приёма событий «Завода» сохранены. |
| 9. Резервные копии | Проверено настоящее создание и восстановление базы: запись до копии сохранилась, добавленная позже исчезла. `integrity_check` прошёл: схема 22, 42 таблицы, WAL и foreign keys включены. Пользователю рекомендована отдельная внешняя копия. |
| 10. Row Level Security | Общей облачной таблицы магазинов и SQL RLS здесь нет. SQLite находится на компьютере магазина; сервер телефона проверяет роли и разрешения. Проверены запреты доступа, а не только скрытие элементов интерфейса. Это не защита базы от владельца операционной системы. |
| 11. Ключи вне фронтенда | Хранение Gemini-ключа выполняется основным процессом через `safeStorage`; интерфейс состояния получает `hasKey`, а не сохранённый ключ. Ввод собственного ключа пользователем остаётся в настройках. Закрытый ключ выпуска лицензий в публичный сайт не добавлялся. |
| 12. Мобильная компоновка | Проверены Chromium/WebKit на 320×568, 390×844, 844×390 и 1440×900: шесть секций, формы, диалоги, ссылки и клавиатурный фокус. Физического iPhone в облачном стенде нет. |
| 13. Страница 404 | Собственная страница с навигацией; опубликованный отсутствующий адрес отвечает HTTP 404. Проверяется существующим контролем публикации. |
| 14. Аналитика | Клиентский модуль есть, учитывает настройку отказа и DNT/GPC. Разрыв приёма Smart Store исправлен в draft PR «Завода»; без развёртывания Worker новая сводка там не появится. Посетитель не связывается с компьютером магазина. |
| 15. Отслеживание ошибок | В приложении уже есть локальный журнал. В лендинг v63 добавлены фиксированные категории ошибок и версия, без текста исключения, стека, URL и значений формы. Центральный сбор ещё ожидает развёртывания «Завода». |
| 16. Конфиденциальность | Публичная страница описывает хранение, внешние сервисы, необязательные события, диагностику, контакт и запрос сведений. Настройка отключения проверена. Это техническая проверка сведений, не юридическое заключение. |
| 17. Условия | Опубликованы подтверждённые продавец-физлицо, проба 14 дней, разовая оплата, лицензия на один компьютер и перенос через поддержку. Цена сообщается в WhatsApp. Возврат предложен владельцу как проект; согласованных условий пока нет, поэтому они не опубликованы. |
| 18. Удаление аккаунта | У лендинга нет личных аккаунтов. Добавлена кнопка запроса удаления сведений у разработчика через WhatsApp; сообщение отправляет пользователь. Сотрудника можно заблокировать и отозвать его входы, сохранив документы магазина. Запрос не удаляет автоматически локальную базу и её копии. |
| 19. Первое знакомство | Проверен первый запуск и путь «настройка → приход → продажа → сдача → остаток → PDF → копия → перезапуск». С установки лендинга есть переход к инструкции первого чека. |

## Диагностика v63

Независимый `scripts/diagnostics.js` принимает только известные `module:<имя>`
и `runtime:exception` / `runtime:rejection`. Сообщение содержит `site`,
`name: error` и `label: v63:<категория>`. За открытие отправляется не больше
пяти разных категорий; повторов и повторных попыток отправки нет.
Ожидаемый `AbortError` не учитывается. Cookie и referrer не прикладываются.
Действуют текущая настройка статистики, DNT/GPC и отказ доступа к хранилищу.
Отказ мониторинга сохраняет работу формы и установщика.

Worker в draft [PR «Завода» №1](https://github.com/Sardorbek505/zavod/pull/1)
принимает только ограниченный формат с разрешённого Origin и выводит категории
в «Гости» → «Сбои страницы». Счётчик использует существующий суточный отпечаток
и не означает число уникальных людей за весь период.
В текущей среде Wrangler не авторизован; развёртывание не выполнено.
CI private-репозитория ранее завершился до запуска шагов, причина не установлена;
локальные проверки не выдаются за успешный удалённый CI.

## Проверки

- 13 Node-тестов лендинга, включая ограничения диагностических сообщений.
- Chromium/WebKit: отказ модуля, дедупликация, отсутствие личных значений
  в сообщении, DNT/GPC/запрет хранилища и работа без мониторинга.
- Проверки готовности и короткого лендинга в обоих движках: формы, история,
  поздние ответы, CSP, документы без JS и остановка WebGL за диалогом.
- 96 тестов приложения в 12 файлах: доступ, роли, пароли, сессии, перебор,
  защита настроек владельца, резервные копии и восстановление.
- Electron smoke: восстановление базы и пользователи телефона в отдельных
  временных профилях, без подключения учебных магазинов к продакшену.
- 39 локальных тестов «Завода», сборка и линтер. Сохранены существовавшие
  предупреждения линтера; реальные посещения и клиенты тестами не создаются.

При переходе к фрагменту `#data` браузер асинхронно посылает `hashchange`;
проверка короткого лендинга теперь ждёт возврата истории после закрытия диалога
и раскрытия ответа, а не нового сетевого перехода. Логика FAQ не менялась.

Electron запущен на Linux. Физические сканер/принтер и установка на настоящей
Windows этой проверкой не подменяются. Ранее проверенные SHA256 установщика и
клиентский путь — в [проверке первого запуска](customer-path-2026-10-27.md).
