# Архитектура и логика сайта — 27 октября 2026

| Изучает требования                     | «О программе» из подвала или поиска                 | Продажи, склад, долги, аренда, интернет, хранение, установка и лицензия |

Лендинг статический. С 28 октября metov.store обслуживает Cloudflare Worker
с разрешёнными публичными файлами; GitHub Pages продолжает публиковать корень
`main` и остаётся origin для отката. Изменения `main` попадают в основной Worker
после отдельной сборки и публикации edge-пакета. Основное содержание присутствует
в HTML: сервер приложения и рендеринг React для индексации не нужны.
На лендинге нет базы клиентов, загрузки накладных, приёма платежей или браузерной
версии Windows-программы. `/demo/` оставлен как переход для старых ссылок в
`/#workspace`; это уже не отдельный демомагазин.

## Загрузка и границы

`app.js?v=66` запускает независимые модули через `Promise.allSettled`. Вход,
скачивание и статистика получают общие правила из `scripts/core.js`; визуальные
модули запускаются независимо. Отказ визуального модуля сохраняет вход и
установку. Версия загрузчика передаётся импортируемым модулям.

Диагностика загружается отдельно и не задерживает эти модули. Отправляются
только фиксированные категории ошибки и публичная версия, до пяти разных
категорий за открытие. Настройка статистики и DNT/GPC действуют также на них;
текст исключения, стек, URL и значения формы не передаются. Приём и сводка
развёрнуты в Cloudflare с обновлением «Завода» 28 октября 2026 года;
подтверждения и оставшиеся проверки — в [отчёте публикации](deployment-2026-10-28.md).

Основные шесть секций: херо, возможности, 3D-касса, телефон, предложение, FAQ.
Установка раскрывается по запросу. Вход и просмотр скриншотов используют
нативные диалоги; фокус, история и поздние ответы учитываются отдельно.
Закрытый FAQ занимает экран, а раскрытые ответы увеличивают высоту раздела:
вложенной вертикальной прокрутки у списка больше нет. Ссылка на ответ сначала
раскрывает его, затем ставит вопрос под фиксированной навигацией. Поздний
переход не меняет положение страницы после новой навигации или открытия диалога.
Просмотр скриншота добавляет одну запись в историю с текущим адресом раздела.
«Назад» закрывает просмотр, «Вперёд» и перезагрузка восстанавливают выбранный
экран. Закрытие возвращает прокрутку и фокус к исходной кнопке, даже если
фрагмент адреса всё ещё указывает на ранее открытый раздел. В `history.state`
хранятся URL публичного изображения, подписи, номер кнопки и позиция прокрутки.
При восстановлении разрешены изображения из `/img/` текущего origin.
Повторное закрытие не отправляет два перехода назад; недоступная History API
оставляет просмотр и обычное закрытие доступными.
Стеклянная навигация скрыта в начале херо. Лента и сцены останавливаются вне
видимости, при скрытии вкладки, прокрутке или открытом диалоге.

3D импортируется при приближении к кассе, а не на первом экране. Рендер ограничен
2× и 2,1 млн пикселей; экраны — настоящие снимки приложения 2880×1800. Окружение
и контактные тени готовятся один раз. При отказе WebGL остаются четыре
изображения той же сцены. Подробности: [качество v56](checkout-quality-v56.md).

## Установка

До запуска JS CTA ведут в `#installation`. На Windows они заменяются ссылкой
официального выпуска. Принимается только стабильный выпуск и точное имя
`SmartStore-Setup-<версия>-x64.exe` с URL репозитория `smart-store-releases`.
Ошибочный ответ или таймаут сохраняет ссылку на официальный список выпусков.

На телефоне, Mac и Linux API выпуска не запрашивается. Копирование подтверждается
после успешной записи; при запрете буфера предлагается ручное копирование.
Системная отправка запускается только нажатием посетителя. Поздний ответ
не превращает ссылку телефона в EXE. Обновления самого приложения находятся
в другом репозитории.

## Вход

Состояния: `idle → checking → redirecting / not-found / unavailable`; неверный
ввод даёт `invalid`. Повторная отправка во время проверки игнорируется.
Редактирование отменяет запрос и позволяет новую проверку. Номер запроса
исключает переход по устаревшему ответу. Таймаут охватывает заголовки и тело.
Закрытие диалога, уход со страницы и восстановление из истории сбрасывают
проверку, сохраняя введённый код без автоматического повторного запроса.

Допустим один код из 2–40 латинских букв, цифр и дефисов либо HTTPS-адрес
соответствующего поддомена metov.store. Служебные `www`, `connect`, `api`,
`admin`, `zavod`, чужие и вложенные домены, credentials и нестандартные порты
отклоняются. Адрес строится локально из проверенного кода; URL из ответа
сервиса не используется. При недоступном сервисе посетитель может явно выбрать
прямой переход. Изменение кода удаляет старую прямую ссылку.

## Статистика и данные

Локальный `scripts/analytics.js` сохраняет протокол счётчиков «Завода»:
`POST https://zavod.metov.store/hit` — сайт, путь, только origin источника;
`POST /act` — название кнопки или раздела, максимум 70 символов. Ввод формы,
параметры URL и фрагменты не включаются. История браузера не перехватывается,
внешний исполняемый SDK не подключается. Необязательные запросы не прикладывают
cookie или credentials. Счётчик загрузки `/download` также необязателен.

Настройка `smart-store-analytics=off`, DNT, GPC или недоступное хранилище
отключают эти запросы. Контроль находится в `privacy.html#analytics-settings`.
Вход и получение установщика от этой настройки не зависят. Серверы по-прежнему
получают технические данные соединения, включая IP; срок их хранения нельзя
определить по коду лендинга. Восстановление статистики после включения настройки
происходит при следующей загрузке главной страницы.

## Публикация, поиск и защита

- `index.html`, `privacy.html`, `programma-dlya-magazina-instrumentov/index.html`
  содержат уникальные title, description, canonical, OG и один H1.
- `sitemap.xml` содержит только эти три канонических URL; `robots.txt` разрешает
  публичные страницы и ресурсы, включая поисковые AI-краулеры.
- JSON-LD связывает сайт и Windows-программу; на документных страницах есть
  видимые хлебные крошки с соответствующей разметкой. Фальшивых цен и оценок нет.
- `llms.txt` — дополнительный список официальных фактов и ссылок, не механизм
  гарантированного ранжирования или рекомендаций.
- `tools/notify-indexnow.py` уведомляет участвующие поисковики о canonical URL
  из sitemap только с `--submit` и после проверки опубликованных файлов.
  Workflow `Notify search engines after publication` вызывает её при изменении
  публичного HTML/файлов обхода на `main`, ожидая публикацию до 240 секунд.
  Проверка публикации может повторяться; POST уведомления — один.
  Документация и тесты не вызывают этот workflow. Кода в браузере нет.
- Корневая `404.html` содержит абсолютные пути к ресурсам и возвращается Pages
  при неизвестном URL с настоящим статусом 404.
- `tools/sync-csp.mjs` создаёт meta CSP с SHA-256 точного содержимого inline-скриптов.
  Внешний JS, eval, объекты и iframe не разрешены. Inline-стили нужны существующим
  адаптивным сценам. Политика не заменяет серверные заголовки.
- CSS и 3D собираются заранее с именами по содержимому. Сохраняется предыдущая
  опубликованная версия. Документы и 404 разделяют небольшой CSS без 3D.

Переводы строк HTML закреплены в `.gitattributes` как LF. Проверка CSP также
нормализует CRLF и CR по правилам HTML-парсера; проверка на Windows не меняет
исходные файлы и по-прежнему отвергает любое изменение inline-скрипта.

После форматирования HTML обновлять CSP: `npm run build:csp`. После CSS —
`npm run build:styles`. Не форматировать inline-скрипты после расчёта хешей без
повторной генерации. Добавленную страницу внести в сборщик стилей, CSP,
`check-site.py`, sitemap, llms и публичную навигацию.

## Проверки

`npm test`, `check:styles`, `check:checkout`, `check:csp`, `check:site` и
`tools/sync-hero-layout.mjs --check` выполняются в CI. `tests/readiness-check.py`
проверяет приватность запросов, конкурирующие отправки, CSP и документы без JS
в Chromium/WebKit. Внешние сервисы заменяются fixtures, реальные магазины и
посетители не создаются. Существующие сценарии проверяют установку, историю,
геометрию и WebGL. Физического iPhone на облачном стенде нет.

`python3 tests/preview-navigation-check.py` проверяет нативные Back/Forward,
повторное закрытие, Escape, перезагрузку, сохранение прокрутки при старом
фрагменте URL и недоступную History API. `BROWSER=webkit` выбирает WebKit;
размеры окна — 320×568, 390×844, 844×390 и 1440×900.

`tools/check-live.py` проверяет опубликованные страницы, TLS, файлы обхода и 404
без входа и событий статистики. Workflow `Public site health` выполняет проверку
каждые 6 часов и вручную; доставку уведомлений определяют настройки GitHub.

Итоги аудита и оставшиеся действия владельца: [готовность v58](site-readiness-2026-10-27.md).
