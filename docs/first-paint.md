# Первый экран без смены дизайна — 24 октября 2026

## Корень проблемы

У херо было два разных представления. В исходном HTML/CSS оставались старые наклонённые карточки. После загрузки модулей, пяти фотографий, их декодирования и подготовки ImageBitmap скрипт рисовал изогнутую ленту на Canvas и добавлял `ribbon-ready`. Этот класс менял геометрию ссылок и скрывал прежние фотографии. На медленной загрузке, особенно в Safari, начальное представление успевало появиться до замены.

Дополнительные сдвиги создавали поздняя установка высоты экрана, появление блока установки без действия пользователя, изменение текста основной кнопки и появление места под управление галереей.

## Одна разметка с первого кадра

- Canvas, ImageBitmap и условное переключение `ribbon-ready` удалены. Галерея использует обычные изображения со `srcset`, процентной геометрией и изогнутыми `clip-path`. Этот же HTML виден до запуска приложения, после запуска и при отсутствии графических API. Раздел не скрывается за экраном загрузки.
- Координаты начального кадра уже записаны в `index.html`. `scripts/ribbon-layout.js` содержит общую нормализованную геометрию для этого кадра и ручного переключения. `tools/sync-hero-layout.mjs` материализует начальное состояние; его режим `--check` включён в CI и ловит рассинхронизацию.
- Адаптивность определяется CSS, без начального JavaScript-пересчёта. Размеры согласованы с прежней изогнутой композицией для телефона, планшета, компьютера и короткого альбомного окна. Скрипт не меняет начальную геометрию, а только подключает кнопки, клавиатуру и свайпы.
- Высота окна фиксируется маленьким синхронным скриптом до таблиц стилей и первого отображения. Поздний модуль viewport принимает уже выбранное значение. Правила стабильной прокрутки на iPhone и пересчёта при повороте сохраняются.
- Главная кнопка сразу содержит «Попробовать бесплатно» и не меняет текст при определении устройства. На телефоне она по-прежнему открывает инструкции установки на Windows. Сам блок инструкций появляется по действию пользователя или прямой ссылке `#installation`, а не вставляется автоматически при старте. CSS `:target` обеспечивает начальное отображение прямой ссылки; JavaScript сохраняет открытое состояние после взаимодействия.
- Под управление галереей заранее зарезервировано 44 px. Его подключение не сдвигает фотографии. Хедер остаётся скрытым в начале и появляется при прокрутке.

Обновление начальной геометрии: `node tools/sync-hero-layout.mjs`, затем форматирование `index.html`. Проверка: `node tools/sync-hero-layout.mjs --check`.

## Проверка

`tests/first-paint-check.py` удерживает приложение на верхнеуровневом await, оставляя HTML/CSS и фотографии видимыми. Снимок сделан до запуска модулей, затем задержка снимается и выполняется повторный снимок. Сравниваются геометрия карточек, херо, управляющей области, текст кнопки, положение следующего раздела и пиксели изображения.

Chromium и отдельный WebKit 26.5: 390×844, 1440×900, 320×568 и 844×390. Во всех восьми проверках — 0 изменений геометрии и 0 изменённых пикселей между первым состоянием и инициализированной страницей. Скриншоты просмотрены. Это проверки браузерных движков, а не физического iPhone.

Запуск: `python tests/first-paint-check.py` и `BROWSER=webkit python tests/first-paint-check.py`. Нужны Playwright, браузеры и Pillow; `FIRST_PAINT_OUTPUT` задаёт каталог скриншотов.

Дополнительно проверены ручная галерея, оригинальные скриншоты, Retina, отключённые графические API, стабильная прокрутка и поворот экрана в Chromium/WebKit, установка и вход, показ навигации после скролла, FAQ, работа без JavaScript, Axe WCAG AA, доменные тесты, синтаксис и форматирование.
