# Smart Store — metov.store

[Smart Store](https://metov.store/) — программа для учёта магазина инструментов
и запчастей на Windows 10/11, 64 бита. Продажи, склад, закупки, долги покупателей,
аренда инструмента и основные отчёты доступны на компьютере. Основной учёт работает
без интернета; интерфейс — на русском и казахском.

Первые 14 дней программа работает без кода активации. Затем для новых операций
нужна лицензия на один компьютер. Стоимость и условия уточняются в поддержке.
Для доступа с телефона компьютер должен оставаться включённым; для внешнего
доступа нужен интернет. AI-функции требуют собственного ключа Gemini.

- [От первого запуска до чека](https://metov.store/programma-dlya-magazina-instrumentov/#first-sale)

В этом репозитории находятся статический лендинг и вход по коду магазина.
GitHub Pages публикует корень `main`; домен задан в `CNAME`. После слияния
изменений отдельные команды на компьютере владельца и токен Cloudflare
для лендинга не нужны. Аналитика и диагностика отправляются в «Завод»
независимо от хостинга страницы. Windows-приложение и сервер подключения
находятся в других репозиториях.

Основной домен обслуживает GitHub Pages; DNS корня и www переключён в DNS only.
Состояние и история: [возврат на GitHub Pages](docs/return-to-github-pages.md).
Production-конфигурация Worker с маршрутами основного домена удалена.
`edge/wrangler.preview.jsonc` остаётся для необязательных тестовых копий.
Старые скрипты `publish-metov-*.mjs` для публикации основного домена больше
не используются.

## Локальная работа

Подключение кабинетов поиска и уведомления об обновлениях:
[инструкция для владельца](docs/search-console-setup.md).

```sh
npm ci
npm run build
npm test
python -m http.server 4173
```

Готовые CSS и 3D-бандл находятся в `assets/`; для обычного просмотра сборка не нужна.
После изменения CSS выполнять `npm run build:styles`; после изменения самой
3D-сцены — `npm run build:checkout`. Сборщики сохраняют предыдущие опубликованные
файлы для кэшированного HTML. После изменения браузерного JS повышать `?v=`
у `app.js`: загрузчик передаёт версию всем модулям. После изменения inline-кода
или JSON-LD и форматирования HTML выполнять `npm run build:csp`. Публикуемый CSP
проверяется в CI; форматирование после генерации требует повторной генерации.

## Страница

В v85 исправлен alpha-blending мобильной оптики: цвет и прозрачность
передаются композитору в одном premultiplied формате, без ярких дуг на фоне.

В v84 мобильное преломление рисует отдельный WebGL-слой над исходными
фотографиями: он работает и при недоступном SVG-фильтре HTML-ленты.
Слой использует часы CSS-анимации, до 30 отрисовок в секунду и останавливается
вместе с лентой. При отказе GPU остаются исходные фото и управление.

В v83 у телефона отдельная зона преломления: эффект виден и на начальном
кадре, где узкая десктопная маска захватывала только однотонный фон.
Сила смещения остаётся как в v82; меняется только мобильная маска.

В v82 зона преломления сужена до внешних 2,5–8% по плавной дуге.
Сила смещения, цветного следа и размытия уменьшена на 10% относительно v81.

В v81 боковое размытие херо заменено настоящим преломлением: контуры
изгибаются и вытягиваются, RGB-каналы смещаются чуть по-разному. Карта
смещения плавно затухает к центру; движение остаётся нативным CSS.

В v80 усилена оптика по краям ленты херо: расфокус 10/14 px, более широкая
зона плавного затухания и заметнее сине-сиреневый блик. Центральные фотографии
остаются чёткими, скорость и управление лентой сохранены.

В v79 удалён весь раздел «Для вашего магазина» с кубами и пункт «Для кого»
из навигации. После возможностей сразу показана касса; модуль и стили
удалённого раздела больше не загружаются.

В v78 кнопки повтора убраны: демонстрации запускаются при появлении карточки
и повторяются после трёх секунд показа результата. Аренда и AI-накладные
оформлены парой компактных плиток. Фотографии возможностей сведены в одну
предметную серию; правила других серий — в [визуальном стиле](docs/visual-style.md).

В v77 возможности возвращены к исходным карточкам: продажа, склад и отчёт.
Внутренние анимации запускаются при появлении карточки. На телефоне доступны
свайп, стрелки и клавиатура. Кубы остались в разделе «Для вашего магазина»:
камера смотрит прямо, без бокового перекоса; верхние грани и встречные
автоповороты сохранены. Фотографии 768/1536, крупный размер и пауза сохранены.

Дополнены условия возврата и хранения сведений, инструкция по квотам Gemini.
Отдельный Cloudflare-пакет сохранён только для preview. Обновление лендинга
выполняет GitHub Pages; аналитика остаётся в ранее опубликованном «Заводе».
Результаты всех списков: [общая проверка](docs/all-checklists-2026-10-27.md).

В v63 добавлены ограниченная диагностика сбоев без текста исключений, инструкция
по восстановлению доступа с телефона и запрос удаления переданных разработчику
сведений. Приём диагностики подготовлен в «Заводе» и ожидает его развёртывания.
Проверены реальные восстановление резервной копии и управление доступом;
подробности — [19 пунктов готовности](docs/reliability-checklist-2026-10-27.md).

В v58 добавлены публичное описание программы, карта сайта, robots.txt, JSON-LD,
социальные метаданные документов и собственная 404. CSP разрешает собственные
скрипты и точные хеши inline-кода. Статистика «Завода» работает локальным модулем
без удалённого SDK и полного referrer; необязательные счётчики отключаются
в настройках конфиденциальности и по DNT/GPC. Дубликаты отправки формы входа
игнорируются. Полный [аудит и дальнейшая работа с поиском](docs/site-readiness-2026-10-27.md).

В v57 иллюстрация «14» и подпись собраны в одну центрированную группу:
текст больше не прижат к низу секции на высоком экране. Заголовок FAQ стоит
над списком вопросов; убрана пустая левая колонка. На невысоких экранах
сохраняются две колонки вопросов. Размер секций остаётся в один экран.

В v56 переработано качество интерактивной кассы: рендер до 2× с бюджетом
2,1 млн пикселей, новые lossless WebP-снимки настоящего приложения 2880×1800,
сглаженная геометрия, отражения студийного окружения и мягкие контактные тени.
Окружение и тени готовятся один раз; дополнительных проходов в каждом кадре нет.
Все четыре резервных изображения заново сняты из той же 3D-сцены.
Ограничения и проверки описаны в [заметке о качестве](docs/checkout-quality-v56.md).

В v55 запуск привязан к 90% самой карточки в видимой области, с отступами
под навигацию и край экрана. Сцена начинается через 240 мс после появления
и остановки прокрутки. На первом экране и при частичном появлении фотографии
таймер анимации не запускается. При полном уходе карточки её анимации
освобождаются; возвращение или обратный свайп запускают новый просмотр с начала.
Небольшая прокрутка внутри блока не перезапускает законченный пример.
`tests/feature-entry-check.py` проверяет эти переходы, удержание касания,
соседние карточки и отмену отложенного старта при быстром уходе.

В v54 ключевые суммы и остатки в карточках увеличены примерно на 15–20%.
Чек проходит этапы 0 → 39 900 → 40 550 ₸ с подсветкой сканирования и появлением
товаров. Склад выделяет обновлённые строки и реагирует на изменение количества;
в отчёте все столбики вырастают волной, затем обновляются выручка и прибыль.
Результат остаётся на экране. Каждый сценарий занимает 5,2 секунды, автоматически
играет один раз и повторяется по кнопке. Используются только transform/opacity;
пауза при прокрутке, касании, уходе из видимости и открытии диалогов сохраняется.
При уменьшении движения и без JS сразу показан итог. Проверка сцен проходит
по реальному WAAPI-времени через сканирование, промежуточную сумму и итог,
проверяет крайние фазы увеличения цифр и освобождение завершённых анимаций.

В v52 три карточки возможностей оформлены единообразно: светлый корпус,
фотография с внутренним отступом и настоящий анимированный мини-интерфейс.
Убраны цветные нижние плашки и двойная рамка виджета. Выбор квадратного или
горизонтального фото учитывает новую рамку (порог 1,27); тест проверяет целые
предметы на фото и отсутствие перекрытия виджетом.

Плавающая навигация имеет один ограниченный backdrop-filter на самой панели,
статичные блики по краям и цвет текста, соответствующий фону раздела.
Тон переключает IntersectionObserver с узкой полосой наблюдения; покадрового
обработчика прокрутки нет. Меню сохраняет плотный фон для читаемости.
`tests/navigation-glass-check.py` проверяет реальную передачу цвета фона,
размытие на пикселях и контраст текста. Если движок не рисует backdrop blur
даже на отдельном простом CSS-образце (WPE headless в текущем стенде), тест
явно сообщает об этом ограничении; Chromium проходит проверку размытия.

В v51 первый экран сразу указывает, что это касса и склад для магазина
инструмента. На телефоне установка предлагает передать ссылку на Windows
через системное меню или скопировать её. Текст передаваемой ссылки объясняет,
что делать на компьютере. Помощь в WhatsApp доступна рядом с установкой;
ссылка только открывает подготовленный вопрос и не отправляет сообщение.
На Windows показаны скачивание и шаги до первого товара. Если API GitHub
недоступен, кнопка прямо сообщает, что откроет страницу скачивания.
Подпись установки в предложении правильна до загрузки JS, без смены текста.

В v50 основной путь сокращён с девяти экранов до шести:

1. Херо с фотолентой и переходом к 3D-кассе.
2. Продажи, склад и контроль — три коротких наглядных примера.
3. Настоящая 3D-касса с тремя приближениями.
4. Телефон: итоги, поиск товара и корзина.
5. Пробные 14 дней, установка и стоимость лицензии.
6. FAQ, включая хранение данных, резервные копии и обновления.

Установка открывается по запросу в `#installation`. Вход по кнопке открывает
компактный нативный диалог `#store`; он поддерживает Escape, «Назад», возврат
фокуса и отмену запроса при закрытии. Исходные экраны открываются в отдельном
просмотрщике. Анимации приостанавливаются за любым открытым диалогом.

Браузерный демомагазин удалён по запросу владельца. Карточки возможностей
открывают исходные скриншоты. `/demo/` перенаправляет старые закладки в кассу,
`#start` — к установке, `#data` — к ответу о резервных копиях.
`tools/demo/` сохраняется для подготовки мокданных и скриншотов настоящего
Windows-приложения; это инструмент разработки изображений, он не загружается
на лендинге.

## Структура

- `index.html`, `privacy.html`, `programma-dlya-magazina-instrumentov/` — лендинг,
  условия и описание продукта; `404.html` — неизвестные адреса.
- `robots.txt`, `sitemap.xml`, `llms.txt` — обход, канонические URL и факты.
- `tools/sync-csp.mjs`, `tools/check-site.py`, `tools/check-live.py` — политика
  скриптов, проверка публикации и публичная доступность.
- `styles.css`, `cinema.css`, `buttons.css`, `screens.css` — основа, херо,
  кнопки и адаптивные экраны.
- `story.css`, `scripts/story.js` — подписи кассы и последовательность телефона.
- `checkout-3d.css`, `scripts/checkout.js`, `scripts/checkout-scene.js` —
  3D-сцена, камера и движение. Параметры: [v44](docs/checkout-3d-v44.md),
  [метки](docs/checkout-hotspots-v46.md), [движение](docs/checkout-motion-v47.md).
- `micro-scenes.css`, `scripts/micro-scenes.js` — короткие анимации возможностей;
  [композиция фотографий](docs/feature-photo-framing-v43.md).
- `trial.css`, `journey.css`, `glass.css` — предложение, установка, навигация
  и диалоги. Источник «14»: [docs/trial-sculpture.md](docs/trial-sculpture.md).
- `scripts/core.js`, `scripts/downloads.js`, `scripts/store.js` — доверенные
  адреса, установщик, передача ссылки на компьютер и вход в магазин.
- `scripts/preview.js`, `scripts/media.js`, `scripts/gallery.js`,
  `scripts/viewport.js`, `scripts/interface.js` — просмотр экранов, отказ
  изображений, лента, стабильная высота и навигация.
- `scripts/hero-optics.js` — независимое мобильное преломление и безопасный
  возврат к исходным фотографиям при отказе GPU.
- `components.css`, `third-party/` — адаптированные компоненты и их лицензии.
- `assets/`, `tools/build-styles.mjs`, `tools/build-checkout.mjs` — готовые
  статические файлы и воспроизводимая сборка.

## Проверка

```sh
npm test
npm run check:styles
npm run check:checkout
npm run check:csp
npm run check:site
BROWSER=chromium python tests/readiness-check.py
node tools/sync-hero-layout.mjs --check
BROWSER=chromium python tests/short-landing-check.py
PLAYWRIGHT_SKIP_VALIDATE_HOST_REQUIREMENTS=1 BROWSER=webkit python tests/short-landing-check.py
```

`tests/short-landing-check.py` проверяет шесть экранов, карточки со скриншотами,
окно входа, историю, фокус, отмену позднего ответа, старые ссылки, отказ модуля,
режим без JS и паузу анимаций за входом. Существующие сценарии
`browser-check.py`, `journey-check.py`, `return-navigation-check.py`,
`loading-check.py` проверяют вход и установку с тестовыми ответами сервисов.
`image-fit-check.py`, `first-paint-check.py`, `native-scroll-check.py`,
`checkout-3d-check.py`, `checkout-ambient-check.py`, `micro-scenes-check.py`
проверяют изображения, первый кадр, прокрутку и движение. Все принимают
`BROWSER=chromium` либо `BROWSER=webkit`; локальный адрес можно заменить
через `SITE_TEST_URL`. Реальные магазины, платежи и сообщения не используются.

CI проверяет доменную логику, сборки, начальную геометрию херо и синтаксис.
После завершения GitHub Pages проверять опубликованную версию. Физический
iPhone в облачном стенде недоступен. Исторические записи в `docs/` описывают
предыдущие версии; текущая структура приведена выше.

После публикации изменённых публичных страниц можно уведомить IndexNow:
`python tools/notify-indexnow.py --submit`. Без `--submit` команда только
показывает список URL. Перед отправкой проверяются опубликованный файл
подтверждения домена и точное совпадение HTML с рабочей копией. Это уведомление
поисковиков, а не подтверждение индексации или позиций; повторять его на каждом
посещении или по расписанию не нужно.

Изменения публичного HTML и файлов обхода на `main` запускают workflow
`Notify search engines after publication`: ожидание совпадающей публикации
до 240 секунд и одно уведомление. Изменения документации и тестов не вызывают
повторную отправку URL. Проверка этой границы без внешних запросов:
`python -m unittest discover -s tests -p 'test_*.py'`.
